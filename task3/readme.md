# **1. Классификация данных (Data Inventory & Classification)**

## **1.1. Класс данных по типу**

| Тип данных                       | Пример                             | Уровень чувствительности | Комментарий                                |
| -------------------------------- | ---------------------------------- | ------------------------ | ------------------------------------------ |
| **PII (Персональные данные)**    | ФИО, телефон, паспорт              | Высокий                  | Идентифицируют личность                    |
| **SPII (Чувствительные данные)** | Медицинская карта, диагноз         | Очень высокий            | По GDPR/HIPAA — защищённая мед. информация |
| **Финансовые данные**            | операции оплаты, номера транзакций | Высокий                  | Не относятся к медданным, но чувствительны |
| **Системные логи**               | логи доступа, ошибки               | Средний                  | Возможна утечка технических метаданных     |
| **Метаданные**                   | ID пациента, event_id              | Средний                  | В комбинации могут деанонимизировать       |
| **Агрегированные данные**        | аналитические отчёты               | Низкий                   | После деперсонализации                     |

## **1.2. Классификация по состоянию данных (Data State Classification)**

| Состояние                        | Что входит                                        | Риски                                |
| -------------------------------- | ------------------------------------------------- | ------------------------------------ |
| **Data in transit** (в передаче) | HTTPS API, интеграции с лабораториями, потоки ETL | Перехват, MITM                       |
| **Data at rest** (в хранении)    | Медхранилище S3, базы CRM/EHR, логи               | Захват дисков, компрометация сервера |
| **Data in use** (в обработке)    | данные в RAM, в процессах EHR                     | Малварь, атаки через память          |
| **Data in analytics**            | выгрузки, витрины аналитики                       | Деанонимизация                       |

## **1.3. Классификация по профилю риска**

| Риск                 | Объекты                     | Комментарий                        |
| -------------------- | --------------------------- | ---------------------------------- |
| **R1 — критический** | Медкарта, диагнозы          | Утечка → уголовные последствия     |
| **R2 — высокий**     | PII, финансы                | Фрод, кража личности               |
| **R3 — средний**     | системные логи              | Возможность выстраивания паттернов |
| **R4 — низкий**      | анонимизированная аналитика | Низкий риск                        |

# **2. Данные, требующие защиты и почему**

| Данные                       | В чём необходимость защиты      | Причины                  |
| ---------------------------- | ------------------------------- | ------------------------ |
| Медицинские записи (EHR)     | Шифрование at rest и in transit | GDPR Art.9, HIPAA        |
| Персональные данные пациента | Шифрование БД, токенизация      | Риск деанонимизации      |
| Результаты анализов          | Шифрование файлов, HSM          | Высокая чувствительность |
| Платёжные данные             | PCI DSS                         | Риск фрода               |
| Логи аудита                  | Целостность и подлинность       | Юридическая значимость   |
| ETL данные                   | Псевдонимизация                 | Аналитика без PII        |

# **3. Архитектурная стратегия Data Encryption In Transit**

## 3.1. Защищённые протоколы

* TLS 1.3 (минимум)
* MTLS (межсервисные вызовы внутри контура)
* HSTS, TLS pinning (мобильное приложение)
* VPN/IPsec для интеграций

## 3.2. Контроль ключей и сертификатов

* PKI + автоматизированный выпуск/ротация (Hashicorp Vault PKI, cert-manager)
* Срок жизни сертификата ≤ 90 дней
* Раздельные trust stores для PROD / DEV

## 3.3. Специализированные меры защиты

* Поддержка Perfect Forward Secrecy (ECDHE)
* Шифрование WebSocket соединений (wss://)
* Rate limiting + DoS shield

# **4. Архитектурная стратегия Data Encryption At Rest**

## 4.1. Шифрование всех хранилищ

* S3 / blob: AES-256-GCM / SSE + KMS
* Базы данных: TDE (Transparent Data Encryption) AES-256
* Логи: Audit Log Encryption (AES-256 + подписи)

## 4.2. Управление ключами (KMS / Vault)

* Хранение master keys в **HSM / Vault**
* Делегирование криптографических операций сервисам (Envelope encryption)
* Автоматическая ротация ключей раз в 90 дней
* RBAC/ABAC на доступ к ключам

## 4.3. Дополнительные меры

* Шифрование кэшей Redis (TLS + encrypted persistent store)
* Шифрование бэкапов (AES-256)
* Изоляция секретов в Secrets Manager (Vault, AWS SM, Kubernetes Secrets with encryption)

# **5. Автоматизированный контроль и мониторинг**

## 5.1. Data Loss Prevention (DLP)

* Контроль передачи PII/SPII внешним системам
* Локатор чувствительных данных в логах
* Блокировка случайных выгрузок

## 5.2. Security Monitoring / SIEM

* Корреляция событий шифрования
* Отслеживание попыток доступа к ключам
* Alert при расшифровке вне расписания
* Необычные запросы к EHR

## 5.3. Compliance Automation

* Регулярные тесты шифрования
* Проверка соблюдения политик хранения данных
* Автоматический аудит доступа (ABAC)

# **6. Реестр программно-аппаратных средств защиты данных**

## Программные средства

| Категория              | Средство                   | Назначение                              |
| ---------------------- | -------------------------- | --------------------------------------- |
| Шифрование на хранении | AES-256, TDE, S3 SSE-KMS   | Защита баз/файлов                       |
| Шифрование в передаче  | TLS 1.3, mTLS              | Защита API                              |
| KMS                    | Hashicorp Vault, AWS KMS   | Управление ключами                      |
| DLP                    | Falcon DLP, InfoWatch      | Автоматический контроль                 |
| SIEM                   | Splunk, ELK + Wazuh        | Мониторинг инцидентов                   |
| Secrets Manager        | Vault, AWS Secrets Manager | Защита секретов                         |
| Pseudonymization       | Custom microservice        | Tokenization/обратимая деперсонализация |
| Data Catalog           | Apache Atlas               | Классификация данных                    |
| ETL Security           | Apache Ranger              | Политики доступа                        |

| Secure backup | Защищённые NAS с криптомодулями      | Шифрованные бэкапы                   |

| ------------------- | ----------------------------- | ----------------------------------------------- |
