# Задание 4. Оценка узких мест при миграции

## Анализ ситуации

Компания **переходит от монолита → к микросервисам** с задачами:

* масштабирование на новые филиалы;
* работа с медицинскими PII/SPII данными;
* интеграция с API лаборатории;
* внедрение CRM, EHR, Data Lake;
* мобильное приложение + API Gateway;
* RBAC/ABAC;
* отказ от Excel/1С-файловой модели.

Это означает миграцию:

* серверов → Kubernetes / облако;
* файловых Excel → централизованные базы и хранилища;
* 1С файлового режима → серверный;
* бизнес-логики → распределённые сервисы;
* интеграций → API;
* данных → Data Lake.

## Выявленные проблемы по категориям

### Инфраструктура

Проблемы:

* один физический сервер — SPOF;
* файловые базы 1С → не масштабируются;
* нет orchestration;
* нет сетевой изоляции.

Риски:

* отказ сервера = остановка бизнеса;
* невозможность внедрить DevOps.

### Программное обеспечение

Проблемы:

* монолит без границ → трудно выделять сервисы;
* legacy-код без тестов;
* tightly coupled к Excel, локальным файлам.

Риски:

* длительная и болезненная миграция;
* риск паралича разработки.

### Данные

Проблемы:

* несогласованные источники данных;
* отсутствие схем;
* PII/SPII без классификации;
* большой объём ручной работы.

Риски:

* потеря данных;
* утечки PII;
* ошибки в аналитике.

### Персонал

Проблемы:

* нет опыта в K8s, микросервисах, API Gateway, OAuth2;
* нет роли Data Engineer.

Риски:

* ошибки конфигурации → утечки данных;
* зависимость от внешних подрядчиков.

### Процессы

Проблемы:

* отсутствуют CI/CD, мониторинг, DevSecOps;
* не определены SLA для сервисов.

Риски:

* частые аварии;
* неэффективная работа команд.

### Интеграции

Проблемы:

* старый механизм OLE → хрупкий;
* отсутствует API Gateway;
* нет стандартизированных контрактов API;
* синхронизация данных разрозненная.

Риски:

* несогласованность данных;
* невозможность расширения.

## Рекомендации по устранению узких мест

### Высокий приоритет (критично)

1. **Внедрить Kubernetes/облако** (устранить SPOF).
2. **API Gateway + сервис авторизации (Keycloak)**.
3. **Создать единый Data Model и Master Data Management**.
4. **Внедрить CI/CD, IaC, DevSecOps**.
5. **Миграция файловых 1С в клиент-серверный режим**.
6. **Создание Data Lake (S3 + каталог данных) для аналитики**.

### Средний приоритет

1. Разделение монолита на bounded contexts (DDD).
2. Обучение персонала микросервисам, DevOps.
3. Стандарты API (OpenAPI 3.1, versioning).
4. Стандарты логирования (Correlation ID) и мониторинга.

### Низкий приоритет

1. Постепенное выведение Excel/сканов.
2. Оптимизация ETL и Data Quality.
3. Автоматизация регламентов.
